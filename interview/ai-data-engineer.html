Python & coding

  1. What does len({'a': 1, 'b': 2, 'a': 3}) return?

    1. It raises an error
    2. 2
    3. 3
    4. 1
    Show answer

    2. Dictionary keys are unique. The second 'a' overwrites the first, leaving 2 keys.

    Learn: Lists and dictionaries: storing many values

  2. You need to check whether 1 million IDs are in a collection of 1 million known IDs. What's the efficient approach?

    1. Keep the known IDs in a list and use `in`
    2. Sort both lists and compare index by index in a nested loop
    3. Convert the IDs to strings first
    4. Put the known IDs in a set and use `in`
    Show answer

    Put the known IDs in a set and use `in`. Membership checks in a set are O(1) on average, but O(n) in a list. With a list this becomes about a trillion comparisons.

    Learn: Lists and dictionaries: storing many values

  3. What does df.groupby('city')['amount'].mean() return?

    1. The overall mean amount
    2. The cities sorted by amount
    3. One average amount per city
    4. A count of rows per city
    Show answer

    One average amount per city. groupby splits the rows by city, then mean() averages 'amount' within each group, giving a Series indexed by city.

    Learn: Pandas: working with tables of data

Statistics & data

  1. Salaries in a team are mostly around ₹8 LPA, with one executive at ₹2 crore. Which best describes a typical salary?

    1. The median
    2. The mean
    3. The sum divided by 2
    4. The maximum
    Show answer

    The median. One extreme value pulls the mean up a lot. The median, the middle value, isn't affected by outliers.

    Learn: Averages and spread: mean, median, variance

  2. Users who turned on a new 'focus mode' spend 30% more time in the app. Can you say focus mode caused it?

    1. Yes, if the sample has more than 1,000 users
    2. No. People who opt in may already be more engaged, so run a randomised A/B test
    3. No, time-in-app can never be measured
    4. Yes, the difference is large
    Show answer

    No. People who opt in may already be more engaged, so run a randomised A/B test. This is self-selection: the opt-in group differs from everyone else. Only random assignment isolates the feature's effect.

    Learn: Correlation vs causation, and sampling bias · Metrics and A/B testing for AI features

SQL & data modelling

  1. You want only the cities with more than 100 orders. Which clause filters those groups?

    1. HAVING COUNT(*) > 100
    2. ORDER BY COUNT(*) > 100
    3. LIMIT 100
    4. WHERE COUNT(*) > 100
    Show answer

    HAVING COUNT(*) > 100. WHERE filters rows before grouping. HAVING filters groups after aggregation.

    Learn: SQL basics: asking a database questions

  2. How do you find customers who have never placed an order?

    1. INNER JOIN orders and keep the matches
    2. SELECT DISTINCT customer_id FROM orders
    3. GROUP BY customer_id HAVING COUNT(*) > 0
    4. LEFT JOIN orders and keep rows where the order id IS NULL
    Show answer

    LEFT JOIN orders and keep rows where the order id IS NULL. A LEFT JOIN keeps every customer. Those with no match have NULL order columns.

    Learn: SQL JOINs: combining tables

  3. Joining 1M orders to a customers table returns 3M rows. What's the most likely cause?

    1. The database is corrupted
    2. Orders are counted twice by default
    3. Duplicate customer IDs in the customers table, so each order matches several rows
    4. The join should have been a LEFT JOIN
    Show answer

    Duplicate customer IDs in the customers table, so each order matches several rows. A join multiplies rows when the key isn't unique on one side. Check uniqueness before you join.

    Learn: SQL JOINs: combining tables · Data quality: catching bad data early

  4. Which expression gives each store's running revenue total, ordered by date?

    1. MAX(amount) OVER (ORDER BY store_id)
    2. COUNT(*) OVER ()
    3. SUM(amount) GROUP BY store_id
    4. SUM(amount) OVER (PARTITION BY store_id ORDER BY sale_date)
    Show answer

    SUM(amount) OVER (PARTITION BY store_id ORDER BY sale_date). A window function with PARTITION BY store and ORDER BY date accumulates the sum row by row within each store.

    Learn: Data modelling: designing tables for analysis

ML fundamentals

  1. Training accuracy is 98% and test accuracy is 65%. What's happening, and what's a reasonable fix?

    1. Underfitting, so add more layers
    2. Everything is fine
    3. Overfitting, so simplify the model, regularise or get more data
    4. The test set is wrong, so delete it
    Show answer

    Overfitting, so simplify the model, regularise or get more data. A large train/test gap means the model memorised the training data. Reduce its complexity, regularise, or add data.

    Learn: Train/test split and overfitting

  2. A fraud model uses 'refund_issued' as a feature and scores 0.99 AUC in testing. What's the problem?

    1. Data leakage: refunds happen after fraud is confirmed, so this information isn't available at prediction time
    2. The feature needs scaling
    3. AUC can't exceed 0.95
    4. Nothing, it's a strong feature
    Show answer

    Data leakage: refunds happen after fraud is confirmed, so this information isn't available at prediction time. Features must only use information available at the moment of prediction. Otherwise test scores are inflated.

    Learn: Feature engineering: turning raw data into useful inputs

  3. For a churn model on a 30-column customer table, what's a strong first choice after a baseline?

    1. A chatbot
    2. Gradient-boosted trees such as XGBoost or LightGBM
    3. A large transformer
    4. K-means clustering
    Show answer

    Gradient-boosted trees such as XGBoost or LightGBM. Boosted trees are usually the most accurate, fastest and most explainable option for tabular data.

    Learn: Decision trees, random forests and boosting

Serving & MLOps

  1. A model's accuracy has dropped slowly over six months with no code changes. What's the most likely cause?

    1. The GPU is overheating
    2. Too many unit tests
    3. A memory leak
    4. Data or concept drift: the real world changed, so monitor the inputs and retrain
    Show answer

    Data or concept drift: the real world changed, so monitor the inputs and retrain. Models are frozen snapshots of the past. When the input data or its relationships change, quality degrades silently.

    Learn: Monitoring models: drift and silent failures

  2. What problem does Docker mainly solve?

    1. 'Works on my machine' problems, by packaging the app with its exact environment
    2. GPU pricing
    3. Model accuracy
    4. Writing SQL
    Show answer

    'Works on my machine' problems, by packaging the app with its exact environment. A container image carries the code, runtime and libraries, so the app runs the same everywhere.

    Learn: Docker: packaging your app so it runs anywhere

RAG & retrieval

  1. Your RAG assistant gives wrong answers. The right document exists but is never retrieved. What do you fix first?

    1. Switch to a bigger LLM
    2. Raise the temperature
    3. Retrieval: chunking, embeddings, hybrid search or re-ranking
    4. Shorten the system prompt
    Show answer

    Retrieval: chunking, embeddings, hybrid search or re-ranking. If the right text never reaches the prompt, no LLM can answer correctly. Measure retrieval separately from generation.

    Learn: RAG: letting an LLM answer from your documents

  2. Company policies change every week and answers must be current. What's the right approach?

    1. Pre-train a new model
    2. Fine-tune a model every week
    3. RAG over the latest documents
    4. Put every policy in the system prompt forever
    Show answer

    RAG over the latest documents. RAG keeps answers current without retraining. Fine-tuning teaches style and skills, not changing facts.

    Learn: RAG: letting an LLM answer from your documents · Fine-tuning and LoRA: specialising a model · AI literacy for decisions: build vs buy, cost and limits

  3. Semantic search fails to find exact product codes like 'SKU-88213'. What helps most?

    1. Lowering the temperature
    2. Removing product codes from documents
    3. A bigger embedding model only
    4. Hybrid search: combine keyword (BM25) and vector search
    Show answer

    Hybrid search: combine keyword (BM25) and vector search. Embeddings capture meaning but are weak on exact identifiers. Keyword search catches those, and hybrid gets both.

    Learn: Embeddings and vector databases: searching by meaning

Data engineering

  1. What does it mean for a pipeline to be idempotent?

    1. It doesn't need a schedule
    2. It runs only once
    3. Running it again for the same period gives the same result, with no duplicates
    4. It never fails
    Show answer

    Running it again for the same period gives the same result, with no duplicates. Re-runs are routine after failures, and idempotency (for example overwrite-by-partition or upserts) prevents double counting.

    Learn: Data pipelines: ETL, Airflow, dbt and Spark

  2. Which use case most needs streaming rather than nightly batch processing?

    1. A yearly HR summary
    2. A monthly finance report
    3. Blocking a fraudulent payment as it happens
    4. Archiving old logs
    Show answer

    Blocking a fraudulent payment as it happens. When decisions must happen in seconds, batch is too late.

    Learn: Streaming data: Kafka and real-time pipelines

  3. Where is the cheapest place to catch bad data?

    1. In the CEO's dashboard
    2. In customer complaints
    3. After the model is retrained
    4. Early in the pipeline, with automated checks that fail the run
    Show answer

    Early in the pipeline, with automated checks that fail the run. The earlier you catch it, the fewer downstream systems it pollutes.

    Learn: Data quality: catching bad data early

  4. In Kafka, what does a consumer group let you do?

    1. Merge topics
    2. Delete messages after reading
    3. Spread a topic's partitions across several consumers, so each message is processed once by the group
    4. Encrypt producers
    Show answer

    Spread a topic's partitions across several consumers, so each message is processed once by the group. Consumers in a group share the work. Separate groups each get their own full copy of the stream.

    Learn: Streaming data: Kafka and real-time pipelines

  5. Design a pipeline that keeps a RAG index fresh as documents change. open question

    A strong answer covers:

    • Change detection (content hashes, CDC or webhooks)
    • Parsing and chunking with metadata, including permissions
    • Embedding, then upserting changed chunks and deleting removed ones
    • Idempotency, retries and backfills
    • Quality and freshness monitoring
    • Cost control (only re-embed what changed)
    Show model answer

    Sources emit change events through webhooks or periodic scans comparing content hashes. Changed documents are parsed, chunked with overlap and tagged with source, section, timestamp and access groups. Only changed chunks are re-embedded and upserted, and chunks from deleted documents are removed. Jobs are idempotent and keyed by document version, so retries and backfills are safe. I'd monitor freshness lag, failed parses and the share of chunks with missing metadata, and run a nightly retrieval check against a small eval set.

    Learn: Data pipelines: ETL, Airflow, dbt and Spark · Embeddings and vector databases: searching by meaning · Data quality: catching bad data early

Communication

  1. Tell me about yourself and why you're moving into this AI role. open question

    A strong answer covers:

    • Current role and years of experience in one or two lines
    • 2–3 transferable skills that matter for this AI role
    • A concrete AI project, with a measurable result
    • Why this specific role fits you (not just 'AI is hot')
    • What you'll bring to the team in the first months
    Show model answer

    I'm a backend engineer with 8 years in fintech, building payment APIs that handle about 2 million requests a day. Over the last six months I've been moving into LLM engineering: I built a support-triage agent with tool calling and an eval suite, which raised correct routing from 71% to 89% on 200 real tickets. This role fits because it combines what I'm already good at, reliable APIs and production debugging, with the agent work I enjoy most. In the first months I'd bring production discipline: tracing, evals and cost controls for your agents.

    Learn: Landing the AI role: resume, applications and interviews

  2. Walk me through an AI or ML project you built end to end. open question

    A strong answer covers:

    • The problem and who it was for
    • The data: source, size and cleaning
    • The approach, and why you chose it over alternatives
    • How you evaluated it, with numbers
    • How it was deployed or used
    • What failed, and what you'd improve next
    Show model answer

    I built a policy assistant for branch staff who spent about 25 minutes a day searching PDFs. I indexed 140 policy documents with chunking and metadata, used hybrid search, and required citations with a 'not found' rule. I chose RAG over fine-tuning because the policies change monthly. On a 60-question eval set built with staff, correct-and-cited answers went from 68% to 90% after I added re-ranking. It's deployed as an internal web app. The main failure was tables in PDFs; next I'd add table-aware parsing.

    Learn: Building a portfolio project that gets interviews

  3. Tell me about a time something you built failed. What did you do? open question

    A strong answer covers:

    • The situation, briefly (STAR format)
    • Your own responsibility, without blaming others
    • How you diagnosed it, step by step
    • The outcome, with numbers if possible
    • What you changed so it doesn't happen again
    Show model answer

    Our nightly data pipeline silently loaded duplicate orders for three days, inflating revenue on a dashboard by 12%. I owned that pipeline. I traced it to a retry that re-appended a partial load, so the job wasn't idempotent. I fixed the data, switched the load to overwrite-by-partition, and added a uniqueness check that fails the run. Since then we've had no duplicate incidents, and I now design every pipeline to be safely re-runnable.

    Learn: Landing the AI role: resume, applications and interviews

AI system design

  1. Design a 'chat with company documents' assistant for 10,000 employees. open question

    A strong answer covers:

    • Ingestion: parsing, chunking with metadata, and keeping the index fresh
    • Permission-aware retrieval (access filters applied before the LLM)
    • Hybrid search plus re-ranking
    • A prompt that requires citations and says 'not found' when unsure
    • Evals and a user feedback loop
    • Security: PII handling, audit logs, data residency
    • Latency and cost controls (caching, model choice)
    Show model answer

    Documents flow from SharePoint and Confluence through a parser into chunks carrying metadata: source, section, updated date and access groups. A change-detection job re-indexes only what changed. At query time I'd authenticate via SSO, filter the search by the user's groups, run hybrid keyword-plus-vector search and re-rank the top results. The prompt asks the model to answer only from the provided sources, cite them, and say when it doesn't know. I'd mask PII and log every question, retrieved documents and answer for audit. Quality comes from a 100-question eval set built with real users, plus thumbs-up/down feedback. Cost and latency are managed with response caching and a smaller model for simple questions.

    Learn: RAG: letting an LLM answer from your documents · Enterprise AI: integration, security and compliance · Evaluating AI: how to know it actually works
