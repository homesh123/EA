Python & coding

  1. What does len({'a': 1, 'b': 2, 'a': 3}) return?

    1. It raises an error
    2. 2
    3. 3
    4. 1
    Show answer

    2. Dictionary keys are unique. The second 'a' overwrites the first, leaving 2 keys.

    Learn: Lists and dictionaries: storing many values

  2. You need to check whether 1 million IDs are in a collection of 1 million known IDs. What's the efficient approach?

    1. Keep the known IDs in a list and use `in`
    2. Sort both lists and compare index by index in a nested loop
    3. Convert the IDs to strings first
    4. Put the known IDs in a set and use `in`
    Show answer

    Put the known IDs in a set and use `in`. Membership checks in a set are O(1) on average, but O(n) in a list. With a list this becomes about a trillion comparisons.

    Learn: Lists and dictionaries: storing many values

  3. What's wrong with `def add(item, basket=[]): basket.append(item); return basket`?

    1. Nothing, it's idiomatic
    2. The default list is created once and shared between calls, so items leak across calls
    3. append returns None, so the function always returns None
    4. Lists can't be default arguments
    Show answer

    The default list is created once and shared between calls, so items leak across calls. Default values are evaluated once, when the function is defined. Use `basket=None` and create a new list inside the function.

    Learn: Python logic: if/else, loops and functions

Deep learning

  1. What does self-attention compute in a transformer?

    1. The order in which to read files
    2. The learning rate per layer
    3. For each token, how much to draw on every other token, giving context-aware representations
    4. A compressed copy of the dataset
    Show answer

    For each token, how much to draw on every other token, giving context-aware representations. Queries and keys produce attention weights, and the values are mixed by those weights, so each token's meaning depends on its context.

    Learn: Transformers and attention: how LLMs read

LLMs & prompting

  1. You need consistent, repeatable answers for extracting invoice fields. How should you set temperature?

    1. High (1.0+)
    2. Change it randomly per request
    3. Low (around 0)
    4. It doesn't matter
    Show answer

    Low (around 0). Low temperature makes outputs focused and repeatable. Higher temperature adds variety, which suits brainstorming.

    Learn: What is an LLM? Tokens, context and temperature

  2. Why do LLMs sometimes state wrong facts confidently?

    1. Only small models do this
    2. Their internet connection is slow
    3. They are lying on purpose
    4. They generate plausible text and don't verify facts unless given sources or tools
    Show answer

    They generate plausible text and don't verify facts unless given sources or tools. Grounding answers in sources (RAG), using tools, and showing citations reduces hallucination.

    Learn: What is an LLM? Tokens, context and temperature · AI safety in products: hallucinations, prompt injection and guardrails

  3. Your code must read the LLM's answer reliably. What's the best approach?

    1. Use a higher temperature
    2. Increase max tokens
    3. Ask for a friendly paragraph and parse it with regex
    4. Ask for structured output (a JSON schema or tool call) and validate it in code
    Show answer

    Ask for structured output (a JSON schema or tool call) and validate it in code. Structured output with validation, such as Pydantic, gives predictable, machine-readable results, with retries on failure.

    Learn: Prompting: giving clear instructions to an LLM · Calling an LLM API: keys, requests and costs

  4. Where should an LLM API key live in your app?

    1. Hard-coded in the source
    2. In an environment variable or a secrets manager
    3. In a public config.json
    4. In the README
    Show answer

    In an environment variable or a secrets manager. Keys in code end up in Git history and get stolen. Load them from the environment or a secrets manager.

    Learn: Calling an LLM API: keys, requests and costs

  5. What is an LLM's context window?

    1. The time limit for a request
    2. The number of users at a time
    3. The size of its training data
    4. The maximum number of tokens (input plus output) the model can consider at once
    Show answer

    The maximum number of tokens (input plus output) the model can consider at once. Prompts, documents, history and the answer all have to fit within the context window.

    Learn: What is an LLM? Tokens, context and temperature

RAG & retrieval

  1. Your RAG assistant gives wrong answers. The right document exists but is never retrieved. What do you fix first?

    1. Switch to a bigger LLM
    2. Raise the temperature
    3. Retrieval: chunking, embeddings, hybrid search or re-ranking
    4. Shorten the system prompt
    Show answer

    Retrieval: chunking, embeddings, hybrid search or re-ranking. If the right text never reaches the prompt, no LLM can answer correctly. Measure retrieval separately from generation.

    Learn: RAG: letting an LLM answer from your documents

Agents & tools

  1. In tool use (function calling), who actually executes the tool?

    1. The user's browser automatically
    2. The LLM, inside the model
    3. Your application code
    4. The model provider's servers always
    Show answer

    Your application code. The model only requests the call. Your code runs it, which is where you validate inputs and enforce permissions.

    Learn: Tool use (function calling): letting an LLM take actions

  2. Your agent calls the same search tool 40 times in a row. What should have prevented this?

    1. Removing the system prompt
    2. A larger model
    3. A higher temperature
    4. Guardrails: a max-steps limit, loop detection and a cost budget
    Show answer

    Guardrails: a max-steps limit, loop detection and a cost budget. Agents need explicit stopping rules and budgets enforced by your code.

    Learn: AI agents: plan, act, observe, repeat

  3. A support agent can issue refunds through a tool. What's the safest design?

    1. Only allow refunds at night
    2. Verify the order, cap amounts and require human approval above a threshold
    3. Let it refund any amount automatically
    4. Hide the tool description
    Show answer

    Verify the order, cap amounts and require human approval above a threshold. High-impact actions need hard limits and human checks outside the model.

    Learn: AI safety in products: hallucinations, prompt injection and guardrails · Tool use (function calling): letting an LLM take actions

  4. What does the Model Context Protocol (MCP) mainly provide?

    1. A standard way to expose tools and data to AI apps, so one connector works with many clients
    2. A fine-tuning method
    3. A vector database
    4. A new LLM architecture
    Show answer

    A standard way to expose tools and data to AI apps, so one connector works with many clients. MCP standardises tool and data integration, like USB-C for AI applications.

    Learn: MCP: a universal plug for AI tools

  5. A business process always has the same 3 steps. What should you build?

    1. A fully autonomous multi-agent system
    2. A deterministic workflow with LLM calls at the steps that need them
    3. A new foundation model
    4. Nothing, because AI can't help
    Show answer

    A deterministic workflow with LLM calls at the steps that need them. Add autonomy only where it clearly helps. Fixed workflows are cheaper, faster and easier to test.

    Learn: AI agents: plan, act, observe, repeat

Evaluation & safety

  1. You changed the prompt, and a few answers you tried look better. What next?

    1. Increase max tokens
    2. Run the full eval set and compare scores before shipping
    3. Ask the model if it improved
    4. Ship it
    Show answer

    Run the full eval set and compare scores before shipping. Spot checks hide regressions. An eval set measures the real effect of each change.

    Learn: Evaluating AI: how to know it actually works

  2. What is prompt injection?

    1. A caching technique
    2. A way to speed up prompts
    3. Adding examples to a prompt
    4. Instructions hidden in user input or documents that try to override the system's rules
    Show answer

    Instructions hidden in user input or documents that try to override the system's rules. Treat documents and user content as untrusted data, limit tool permissions, and check outputs.

    Learn: AI safety in products: hallucinations, prompt injection and guardrails

Communication

  1. Tell me about yourself and why you're moving into this AI role. open question

    A strong answer covers:

    • Current role and years of experience in one or two lines
    • 2–3 transferable skills that matter for this AI role
    • A concrete AI project, with a measurable result
    • Why this specific role fits you (not just 'AI is hot')
    • What you'll bring to the team in the first months
    Show model answer

    I'm a backend engineer with 8 years in fintech, building payment APIs that handle about 2 million requests a day. Over the last six months I've been moving into LLM engineering: I built a support-triage agent with tool calling and an eval suite, which raised correct routing from 71% to 89% on 200 real tickets. This role fits because it combines what I'm already good at, reliable APIs and production debugging, with the agent work I enjoy most. In the first months I'd bring production discipline: tracing, evals and cost controls for your agents.

    Learn: Landing the AI role: resume, applications and interviews

  2. Walk me through an AI or ML project you built end to end. open question

    A strong answer covers:

    • The problem and who it was for
    • The data: source, size and cleaning
    • The approach, and why you chose it over alternatives
    • How you evaluated it, with numbers
    • How it was deployed or used
    • What failed, and what you'd improve next
    Show model answer

    I built a policy assistant for branch staff who spent about 25 minutes a day searching PDFs. I indexed 140 policy documents with chunking and metadata, used hybrid search, and required citations with a 'not found' rule. I chose RAG over fine-tuning because the policies change monthly. On a 60-question eval set built with staff, correct-and-cited answers went from 68% to 90% after I added re-ranking. It's deployed as an internal web app. The main failure was tables in PDFs; next I'd add table-aware parsing.

    Learn: Building a portfolio project that gets interviews

  3. Tell me about a time something you built failed. What did you do? open question

    A strong answer covers:

    • The situation, briefly (STAR format)
    • Your own responsibility, without blaming others
    • How you diagnosed it, step by step
    • The outcome, with numbers if possible
    • What you changed so it doesn't happen again
    Show model answer

    Our nightly data pipeline silently loaded duplicate orders for three days, inflating revenue on a dashboard by 12%. I owned that pipeline. I traced it to a retry that re-appended a partial load, so the job wasn't idempotent. I fixed the data, switched the load to overwrite-by-partition, and added a uniqueness check that fails the run. Since then we've had no duplicate incidents, and I now design every pipeline to be safely re-runnable.

    Learn: Landing the AI role: resume, applications and interviews

AI system design

  1. Design a 'chat with company documents' assistant for 10,000 employees. open question

    A strong answer covers:

    • Ingestion: parsing, chunking with metadata, and keeping the index fresh
    • Permission-aware retrieval (access filters applied before the LLM)
    • Hybrid search plus re-ranking
    • A prompt that requires citations and says 'not found' when unsure
    • Evals and a user feedback loop
    • Security: PII handling, audit logs, data residency
    • Latency and cost controls (caching, model choice)
    Show model answer

    Documents flow from SharePoint and Confluence through a parser into chunks carrying metadata: source, section, updated date and access groups. A change-detection job re-indexes only what changed. At query time I'd authenticate via SSO, filter the search by the user's groups, run hybrid keyword-plus-vector search and re-rank the top results. The prompt asks the model to answer only from the provided sources, cite them, and say when it doesn't know. I'd mask PII and log every question, retrieved documents and answer for audit. Quality comes from a 100-question eval set built with real users, plus thumbs-up/down feedback. Cost and latency are managed with response caching and a smaller model for simple questions.

    Learn: RAG: letting an LLM answer from your documents · Enterprise AI: integration, security and compliance · Evaluating AI: how to know it actually works

  2. Design an agent that triages customer-support tickets. open question

    A strong answer covers:

    • Tools (via MCP or functions): ticket lookup, order lookup, help-doc search, draft reply
    • Workflow vs autonomy: where the agent decides and where the steps are fixed
    • Guardrails: max steps, cost budget, human approval for refunds
    • Prompt-injection defences: tickets are untrusted data
    • An eval set measuring task success, steps and cost
    • Observability: a trace per run
    Show model answer

    I'd expose tools through an MCP server: get_ticket, get_order, search_help_docs and draft_reply. The flow is mostly fixed: classify, gather context, draft. The agent only chooses which lookups it needs. Guardrails are enforced in code: at most 8 steps, a per-ticket cost budget, refunds only proposed and never executed without human approval, and ticket text treated as data, so instructions inside a ticket are ignored. I'd build 50 eval tickets with expected routing and reply quality, track success rate, steps and cost per ticket, and add injection test cases. Every run is traced for debugging.

    Learn: AI agents: plan, act, observe, repeat · MCP: a universal plug for AI tools · AI safety in products: hallucinations, prompt injection and guardrails · Evaluating AI: how to know it actually works
