Statistics & data

  1. Salaries in a team are mostly around ₹8 LPA, with one executive at ₹2 crore. Which best describes a typical salary?

    1. The median
    2. The mean
    3. The sum divided by 2
    4. The maximum
    Show answer

    The median. One extreme value pulls the mean up a lot. The median, the middle value, isn't affected by outliers.

    Learn: Averages and spread: mean, median, variance

  2. Users who turned on a new 'focus mode' spend 30% more time in the app. Can you say focus mode caused it?

    1. Yes, if the sample has more than 1,000 users
    2. No. People who opt in may already be more engaged, so run a randomised A/B test
    3. No, time-in-app can never be measured
    4. Yes, the difference is large
    Show answer

    No. People who opt in may already be more engaged, so run a randomised A/B test. This is self-selection: the opt-in group differs from everyone else. Only random assignment isolates the feature's effect.

    Learn: Correlation vs causation, and sampling bias · Metrics and A/B testing for AI features

SQL & data modelling

  1. You want only the cities with more than 100 orders. Which clause filters those groups?

    1. HAVING COUNT(*) > 100
    2. ORDER BY COUNT(*) > 100
    3. LIMIT 100
    4. WHERE COUNT(*) > 100
    Show answer

    HAVING COUNT(*) > 100. WHERE filters rows before grouping. HAVING filters groups after aggregation.

ML fundamentals

  1. Training accuracy is 98% and test accuracy is 65%. What's happening, and what's a reasonable fix?

    1. Underfitting, so add more layers
    2. Everything is fine
    3. Overfitting, so simplify the model, regularise or get more data
    4. The test set is wrong, so delete it
    Show answer

    Overfitting, so simplify the model, regularise or get more data. A large train/test gap means the model memorised the training data. Reduce its complexity, regularise, or add data.

    Learn: Train/test split and overfitting

  2. A fraud model is 99% accurate, and 1% of transactions are fraud. What's your first reaction?

    1. Increase the epochs
    2. Accuracy is the only metric that matters
    3. Great, ship it
    4. Compare against the baseline and check precision and recall, because predicting 'not fraud' for everything also scores 99%
    Show answer

    Compare against the baseline and check precision and recall, because predicting 'not fraud' for everything also scores 99%. With rare classes, accuracy is misleading. Precision and recall show whether fraud is actually being caught.

    Learn: Measuring models: accuracy, precision and recall

  3. For a cancer-screening model, which metric should you usually prioritise?

    1. Model size
    2. Recall
    3. Training speed
    4. Precision
    Show answer

    Recall. Missing a real case is far more costly than a false alarm, which only leads to another test.

    Learn: Measuring models: accuracy, precision and recall

LLMs & prompting

  1. You need consistent, repeatable answers for extracting invoice fields. How should you set temperature?

    1. High (1.0+)
    2. Change it randomly per request
    3. Low (around 0)
    4. It doesn't matter
    Show answer

    Low (around 0). Low temperature makes outputs focused and repeatable. Higher temperature adds variety, which suits brainstorming.

    Learn: What is an LLM? Tokens, context and temperature

  2. Why do LLMs sometimes state wrong facts confidently?

    1. Only small models do this
    2. Their internet connection is slow
    3. They are lying on purpose
    4. They generate plausible text and don't verify facts unless given sources or tools
    Show answer

    They generate plausible text and don't verify facts unless given sources or tools. Grounding answers in sources (RAG), using tools, and showing citations reduces hallucination.

    Learn: What is an LLM? Tokens, context and temperature · AI safety in products: hallucinations, prompt injection and guardrails

  3. What is an LLM's context window?

    1. The time limit for a request
    2. The number of users at a time
    3. The size of its training data
    4. The maximum number of tokens (input plus output) the model can consider at once
    Show answer

    The maximum number of tokens (input plus output) the model can consider at once. Prompts, documents, history and the answer all have to fit within the context window.

    Learn: What is an LLM? Tokens, context and temperature

  4. In simple words, what is an LLM, and what is one important limitation? open question

    A strong answer covers:

    • It predicts the next token, trained on huge amounts of text
    • Tokens and the context window
    • It generates plausible text, not verified facts
    • The hallucination limitation, with an example
    • A mitigation: RAG, tools, citations
    Show model answer

    An LLM is a model trained on a huge amount of text to predict the next word, or token. Doing that at scale lets it write, summarise and answer questions. It works within a context window, a limit on how much text it can consider at once. A key limitation is that it produces plausible text rather than checked facts, so it can confidently state something wrong. You reduce this by giving it trusted sources at question time (RAG), asking for citations, and using tools for calculations or live data.

    Learn: What is an LLM? Tokens, context and temperature · RAG: letting an LLM answer from your documents

RAG & retrieval

  1. Company policies change every week and answers must be current. What's the right approach?

    1. Pre-train a new model
    2. Fine-tune a model every week
    3. RAG over the latest documents
    4. Put every policy in the system prompt forever
    Show answer

    RAG over the latest documents. RAG keeps answers current without retraining. Fine-tuning teaches style and skills, not changing facts.

    Learn: RAG: letting an LLM answer from your documents · Fine-tuning and LoRA: specialising a model · AI literacy for decisions: build vs buy, cost and limits

Evaluation & safety

  1. You changed the prompt, and a few answers you tried look better. What next?

    1. Increase max tokens
    2. Run the full eval set and compare scores before shipping
    3. Ask the model if it improved
    4. Ship it
    Show answer

    Run the full eval set and compare scores before shipping. Spot checks hide regressions. An eval set measures the real effect of each change.

    Learn: Evaluating AI: how to know it actually works

  2. When is LLM-as-judge most trustworthy?

    1. When it uses a clear rubric and its grades are checked against human labels
    2. Never
    3. When the judge is the same model and prompt that produced the answer
    4. When it's asked 'is this good?' with no criteria
    Show answer

    When it uses a clear rubric and its grades are checked against human labels. Clear criteria and calibration against human judgement make automated grading reliable enough to track changes.

    Learn: Evaluating AI: how to know it actually works

Product & business

  1. A client says, 'Use AI to stop customers leaving.' What's the best first step?

    1. Agree what 'leaving' means, measure the baseline and check what data exists
    2. Build a chatbot
    3. Train a deep learning model
    4. Buy GPUs
    Show answer

    Agree what 'leaving' means, measure the baseline and check what data exists. Without a definition, a baseline and data, any solution is a guess.

    Learn: Problem framing: should AI solve this, and how?

  2. A company wants an internal Q&A bot over its HR policies. What's the right first approach?

    1. Hire a research lab
    2. Train a foundation model
    3. Rules only
    4. A model API with RAG over the policy documents
    Show answer

    A model API with RAG over the policy documents. API plus RAG is fast, cheap and keeps answers grounded and current.

    Learn: AI literacy for decisions: build vs buy, cost and limits · RAG: letting an LLM answer from your documents

  3. Why are users randomly assigned in an A/B test?

    1. It's easier to code
    2. To hide results from managers
    3. To make the test shorter
    4. So the feature is the only systematic difference between the groups, which lets you claim causation
    Show answer

    So the feature is the only systematic difference between the groups, which lets you claim causation. Randomisation balances every other factor across the two groups.

    Learn: Metrics and A/B testing for AI features

  4. Which section does an AI PRD need that normal PRDs often lack?

    1. A hiring plan
    2. A colour palette
    3. A competitor list
    4. An eval plan with a quality bar and launch criteria for AI output
    Show answer

    An eval plan with a quality bar and launch criteria for AI output. AI output varies, so you must define upfront how quality is measured and what's good enough to launch.

    Learn: Writing an AI product spec (PRD) with an eval plan

  5. Which design choice builds the most user trust in AI answers?

    1. Showing sources and letting users edit before acting
    2. Hiding that AI was used
    3. Longer answers
    4. Removing feedback buttons
    Show answer

    Showing sources and letting users edit before acting. People trust what they can verify and control.

    Learn: UX for AI features: designing for uncertainty

  6. In an A/B test for an AI feature, what is a guardrail metric?

    1. The p-value
    2. The main success metric
    3. The number of users in the test
    4. A metric that must not get worse, such as complaints, cost or latency, while you improve the main one
    Show answer

    A metric that must not get worse, such as complaints, cost or latency, while you improve the main one. Guardrails stop you shipping a 'win' that quietly hurts something important.

    Learn: Metrics and A/B testing for AI features

  7. A bank wants 'AI for customer service'. How do you run the first two weeks? open question

    A strong answer covers:

    • Discovery with stakeholders and frontline agents
    • Baseline metrics (volumes, handling time, CSAT) and data access
    • Pick one high-value, low-risk slice
    • A rapid prototype on real data
    • Security and compliance involved early
    • Clear success criteria and a proposal for next steps
    Show model answer

    In week one I'd interview the support leadership, the frontline agents and the security team, and pull baseline numbers: ticket volumes by category, handling time, CSAT and escalation rates. I'd pick one slice that's frequent and low-risk, for example card-status and policy questions, and confirm data access and compliance constraints early. In week two I'd build a prototype on real, masked data, such as an agent-assist tool that drafts answers with citations, and test it with five agents. I'd finish with a one-page proposal: measured impact, risks and mitigations, and a pilot plan with success criteria.

    Learn: Problem framing: should AI solve this, and how? · Explaining AI to non-technical people

  8. How would you measure whether an AI summarisation feature is successful? open question

    A strong answer covers:

    • A user-outcome metric (e.g. time saved, tasks completed)
    • Offline quality evals (faithfulness, completeness) with a rubric
    • Adoption and retention
    • Guardrails: complaints, errors, cost, latency
    • An A/B test for causality
    • Qualitative feedback
    Show model answer

    The primary metric would be user outcome, for example time to resolve a case for people who use summaries. Before launch, I'd score faithfulness and completeness on an eval set with a rubric, aiming for a quality bar such as 90% with no critical omissions. After launch, I'd run an A/B test measuring time saved, with guardrails on complaint rate, edit rate, latency and cost per summary. I'd also track adoption and repeat use, and read 👎 feedback weekly to find failure patterns.

    Learn: Metrics and A/B testing for AI features · Evaluating AI: how to know it actually works · Writing an AI product spec (PRD) with an eval plan

Communication

  1. Tell me about yourself and why you're moving into this AI role. open question

    A strong answer covers:

    • Current role and years of experience in one or two lines
    • 2–3 transferable skills that matter for this AI role
    • A concrete AI project, with a measurable result
    • Why this specific role fits you (not just 'AI is hot')
    • What you'll bring to the team in the first months
    Show model answer

    I'm a backend engineer with 8 years in fintech, building payment APIs that handle about 2 million requests a day. Over the last six months I've been moving into LLM engineering: I built a support-triage agent with tool calling and an eval suite, which raised correct routing from 71% to 89% on 200 real tickets. This role fits because it combines what I'm already good at, reliable APIs and production debugging, with the agent work I enjoy most. In the first months I'd bring production discipline: tracing, evals and cost controls for your agents.

    Learn: Landing the AI role: resume, applications and interviews

  2. Walk me through an AI or ML project you built end to end. open question

    A strong answer covers:

    • The problem and who it was for
    • The data: source, size and cleaning
    • The approach, and why you chose it over alternatives
    • How you evaluated it, with numbers
    • How it was deployed or used
    • What failed, and what you'd improve next
    Show model answer

    I built a policy assistant for branch staff who spent about 25 minutes a day searching PDFs. I indexed 140 policy documents with chunking and metadata, used hybrid search, and required citations with a 'not found' rule. I chose RAG over fine-tuning because the policies change monthly. On a 60-question eval set built with staff, correct-and-cited answers went from 68% to 90% after I added re-ranking. It's deployed as an internal web app. The main failure was tables in PDFs; next I'd add table-aware parsing.

    Learn: Building a portfolio project that gets interviews

  3. Tell me about a time something you built failed. What did you do? open question

    A strong answer covers:

    • The situation, briefly (STAR format)
    • Your own responsibility, without blaming others
    • How you diagnosed it, step by step
    • The outcome, with numbers if possible
    • What you changed so it doesn't happen again
    Show model answer

    Our nightly data pipeline silently loaded duplicate orders for three days, inflating revenue on a dashboard by 12%. I owned that pipeline. I traced it to a retry that re-appended a partial load, so the job wasn't idempotent. I fixed the data, switched the load to overwrite-by-partition, and added a uniqueness check that fails the run. Since then we've had no duplicate incidents, and I now design every pipeline to be safely re-runnable.

    Learn: Landing the AI role: resume, applications and interviews
