Python & coding

  1. What does len({'a': 1, 'b': 2, 'a': 3}) return?

    1. It raises an error
    2. 2
    3. 3
    4. 1
    Show answer

    2. Dictionary keys are unique. The second 'a' overwrites the first, leaving 2 keys.

    Learn: Lists and dictionaries: storing many values

  2. What's wrong with `def add(item, basket=[]): basket.append(item); return basket`?

    1. Nothing, it's idiomatic
    2. The default list is created once and shared between calls, so items leak across calls
    3. append returns None, so the function always returns None
    4. Lists can't be default arguments
    Show answer

    The default list is created once and shared between calls, so items leak across calls. Default values are evaluated once, when the function is defined. Use `basket=None` and create a new list inside the function.

    Learn: Python logic: if/else, loops and functions

ML fundamentals

  1. Training accuracy is 98% and test accuracy is 65%. What's happening, and what's a reasonable fix?

    1. Underfitting, so add more layers
    2. Everything is fine
    3. Overfitting, so simplify the model, regularise or get more data
    4. The test set is wrong, so delete it
    Show answer

    Overfitting, so simplify the model, regularise or get more data. A large train/test gap means the model memorised the training data. Reduce its complexity, regularise, or add data.

    Learn: Train/test split and overfitting

Serving & MLOps

  1. A model's accuracy has dropped slowly over six months with no code changes. What's the most likely cause?

    1. The GPU is overheating
    2. Too many unit tests
    3. A memory leak
    4. Data or concept drift: the real world changed, so monitor the inputs and retrain
    Show answer

    Data or concept drift: the real world changed, so monitor the inputs and retrain. Models are frozen snapshots of the past. When the input data or its relationships change, quality degrades silently.

    Learn: Monitoring models: drift and silent failures

  2. In a model API, where should the model be loaded?

    1. Once at startup, then reused for every request
    2. Only during testing
    3. Inside the predict function, on every request
    4. In the browser
    Show answer

    Once at startup, then reused for every request. Loading can take seconds. Doing it per request makes every request slow.

    Learn: Serving a model as an API with FastAPI

  3. What problem does Docker mainly solve?

    1. 'Works on my machine' problems, by packaging the app with its exact environment
    2. GPU pricing
    3. Model accuracy
    4. Writing SQL
    Show answer

    'Works on my machine' problems, by packaging the app with its exact environment. A container image carries the code, runtime and libraries, so the app runs the same everywhere.

    Learn: Docker: packaging your app so it runs anywhere

  4. What does a Kubernetes HorizontalPodAutoscaler do?

    1. Encrypts secrets
    2. Builds Docker images
    3. Adds or removes pod replicas based on load metrics
    4. Restarts the cluster nightly
    Show answer

    Adds or removes pod replicas based on load metrics. The HPA watches CPU, memory or custom metrics and changes the replica count.

    Learn: Kubernetes: running containers at scale

  5. Your LLM GPU runs at 20% utilisation while users wait. What helps most?

    1. A bigger model
    2. Buying more GPUs
    3. An inference server with continuous batching, such as vLLM
    4. Turning off caching
    Show answer

    An inference server with continuous batching, such as vLLM. Batching packs many requests onto the GPU at once, which raises throughput and cuts cost per request.

    Learn: Serving LLMs efficiently: GPUs, batching and cost

  6. What's the main benefit of a model registry?

    1. Versioned, approved models with stages, so deployments are traceable and rollback is instant
    2. Automatic feature engineering
    3. Free GPUs
    4. Faster training
    Show answer

    Versioned, approved models with stages, so deployments are traceable and rollback is instant. You always know which model is in production and can switch back to the previous version in one step.

    Learn: MLOps: experiment tracking and model registries

  7. What does 'p95 latency = 800 ms' mean?

    1. The server handles 95 requests a second
    2. The average request takes 800 ms
    3. 5% of requests fail
    4. 95% of requests finish in 800 ms or less
    Show answer

    95% of requests finish in 800 ms or less. Percentiles describe the slow tail, which is what users notice. Averages hide it.

    Learn: Serving LLMs efficiently: GPUs, batching and cost

  8. Why add a readiness probe to a model-serving pod?

    1. To delete old logs
    2. To pick the GPU type
    3. So traffic is only sent once the model has loaded and the pod can serve
    4. To make the image smaller
    Show answer

    So traffic is only sent once the model has loaded and the pod can serve. Without it, requests hit pods that are still loading the model and fail.

    Learn: Kubernetes: running containers at scale

LLMs & prompting

  1. Where should an LLM API key live in your app?

    1. Hard-coded in the source
    2. In an environment variable or a secrets manager
    3. In a public config.json
    4. In the README
    Show answer

    In an environment variable or a secrets manager. Keys in code end up in Git history and get stolen. Load them from the environment or a secrets manager.

    Learn: Calling an LLM API: keys, requests and costs

Communication

  1. Tell me about yourself and why you're moving into this AI role. open question

    A strong answer covers:

    • Current role and years of experience in one or two lines
    • 2–3 transferable skills that matter for this AI role
    • A concrete AI project, with a measurable result
    • Why this specific role fits you (not just 'AI is hot')
    • What you'll bring to the team in the first months
    Show model answer

    I'm a backend engineer with 8 years in fintech, building payment APIs that handle about 2 million requests a day. Over the last six months I've been moving into LLM engineering: I built a support-triage agent with tool calling and an eval suite, which raised correct routing from 71% to 89% on 200 real tickets. This role fits because it combines what I'm already good at, reliable APIs and production debugging, with the agent work I enjoy most. In the first months I'd bring production discipline: tracing, evals and cost controls for your agents.

    Learn: Landing the AI role: resume, applications and interviews

  2. Walk me through an AI or ML project you built end to end. open question

    A strong answer covers:

    • The problem and who it was for
    • The data: source, size and cleaning
    • The approach, and why you chose it over alternatives
    • How you evaluated it, with numbers
    • How it was deployed or used
    • What failed, and what you'd improve next
    Show model answer

    I built a policy assistant for branch staff who spent about 25 minutes a day searching PDFs. I indexed 140 policy documents with chunking and metadata, used hybrid search, and required citations with a 'not found' rule. I chose RAG over fine-tuning because the policies change monthly. On a 60-question eval set built with staff, correct-and-cited answers went from 68% to 90% after I added re-ranking. It's deployed as an internal web app. The main failure was tables in PDFs; next I'd add table-aware parsing.

    Learn: Building a portfolio project that gets interviews

  3. Tell me about a time something you built failed. What did you do? open question

    A strong answer covers:

    • The situation, briefly (STAR format)
    • Your own responsibility, without blaming others
    • How you diagnosed it, step by step
    • The outcome, with numbers if possible
    • What you changed so it doesn't happen again
    Show model answer

    Our nightly data pipeline silently loaded duplicate orders for three days, inflating revenue on a dashboard by 12%. I owned that pipeline. I traced it to a retry that re-appended a partial load, so the job wasn't idempotent. I fixed the data, switched the load to overwrite-by-partition, and added a uniqueness check that fails the run. Since then we've had no duplicate incidents, and I now design every pipeline to be safely re-runnable.

    Learn: Landing the AI role: resume, applications and interviews

AI system design

  1. Design an LLM serving platform shared by multiple product teams. open question

    A strong answer covers:

    • Inference servers with batching (e.g. vLLM) on GPU node pools
    • Autoscaling on queue depth or GPU metrics
    • A gateway: auth, per-team rate limits and budgets, routing and fallback across models or providers
    • Caching for repeated prompts
    • Observability: time to first token, p95, errors and cost per team
    • Model versioning and safe rollouts (canary)
    Show model answer

    Teams call a single gateway that handles authentication, per-team quotas and budgets, and routing: to self-hosted models on vLLM for high-volume workloads, and to external APIs as a fallback or for frontier capability. Self-hosted models run on GPU node pools in Kubernetes, autoscaled on queue depth, with continuous batching to keep utilisation high. A semantic or exact-match cache absorbs repeated prompts. Dashboards show time to first token, tokens per second, p95 latency, error rate and cost per team. New model versions roll out as canaries with automatic rollback if errors or latency regress.

    Learn: Serving LLMs efficiently: GPUs, batching and cost · Kubernetes: running containers at scale · Monitoring models: drift and silent failures
