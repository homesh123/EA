🧰 Tool use (function calling): letting an LLM take actions

EnglishHinglish

🏠 Real-life example

A smart receptionist can't see the doctor's calendar herself, but she can call the calendar system: 'Is Dr. Mehta free at 4 pm?' She uses the answer to reply to you. Tool use gives an LLM the same ability. It can't fetch live data by itself, but it can ask your code to run a function and then use the result.

💡 In simple words

You describe tools to the model: a name, what each does, and its input parameters as a JSON schema. When a question needs a tool, the model replies with a tool call ('get_order_status', order_id='A123') instead of text. Your code runs the real function and sends the result back, and the model writes the final answer using it. This is how chatbots check orders, book tickets or query databases. Your code stays in control: validate inputs, check permissions, and require human approval for risky actions like refunds.

🎬 See how it works

The model never calls the API itself. It asks your code to, your code runs it, and the model writes the answer from the result.

🔑 Key terms

Tool / function
An action your code exposes to the model, like search or a calculator.
JSON schema
A description of a tool's inputs and their types.
Human-in-the-loop
A person approves important actions before they happen.

👀 See it in action

text
User:   "Where is my order A123?"
Model → tool_call: get_order_status(order_id="A123")
Your code runs it → {"status": "out for delivery", "eta": "7:40 pm"}
Model:  "Your order is out for delivery and should arrive by 7:40 pm 🛵"

The model decides when to use a tool. Your code does the real work.

✅ Quick check

Who actually executes a tool call?

  1. Your application code
  2. The user
  3. The LLM itself, inside the model
Show answer

A. Your application code: The model only requests the call. Your code runs it, so you control permissions and safety.

📌 Remember

The model asks, your code acts. Validate everything.
