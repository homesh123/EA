🏗️ Data modelling: analysis ke liye tables design karna

EnglishHinglish

🏠 Real-life example

Supermarket ka bill batata hai kya hua: items, quantity, amount. Yeh 'fact' hai. Alag se store products (brand, category) aur stores (city, size) ki details rakhta hai. Yeh 'dimensions' hain. Bills ko halka rakhna aur details ko unki apni tables mein rakhna har report ko fast aur saaf banata hai.

💡 Aasaan shabdon mein

Analytics databases (BigQuery ya Snowflake jaise data warehouses) app databases se alag design hote hain. Classic design star schema hai: beech mein events (sales, clicks, trips) ki fact table, numeric measures ke saath, aur uske chaaron taraf dimension tables jo kaun, kya, kahan aur kab describe karti hain. Window functions, jaise running totals, ranks aur 'pichhli value', bina messy self-joins ke sequences analyse karne dete hain. Achha model common sawaalon ko aasaan aur galat jawaabon ko mushkil bana deta hai.

🔑 Key terms

Fact table
Numbers wale events, jaise har sale aur uska amount.
Dimension table
Describe karne wali details, jaise product ka naam ya store ki city.
Window function
Related rows pe calculation, jaise rank ya running total.

👀 Example dekho

sql
SELECT store_id, sale_date, amount,
       SUM(amount) OVER (PARTITION BY store_id ORDER BY sale_date) AS running_total
FROM fact_sales;

Har store ka running total, bina self-join ke.

✅ Quick check

Star schema mein 'product category' column kahan hona chahiye?

  1. Har table mein repeat
  2. Fact table mein
  3. Product dimension table mein
Jawaab dekho

C. Product dimension table mein: Category product ko describe karti hai, isliye woh product dimension mein rehti hai, jisse fact table judti hai.

📌 Yaad rakho

Facts = kya hua (numbers). Dimensions = descriptions.
