🌊 Streaming data: Kafka aur real-time pipelines

EnglishHinglish

🏠 Real-life example

Batch processing subah ka akhbaar padhne jaisa hai: kal ki khabrein, sab ek saath. Streaming live cricket score app jaisa hai: har ball pe turant update. Fraud detection, live delivery tracking aur real-time recommendations ko live-score wala tareeka chahiye.

💡 Aasaan shabdon mein

Streaming mein events (click, payment, GPS ping) lagaataar bahte rehte hain. Apache Kafka standard backbone hai: producers events ko topics mein likhte hain, Kafka unhe order mein durably store karta hai, aur consumers apni speed se padhte hain. Stream processors (Spark Structured Streaming, Flink) chalte-chalte cheezein calculate karte hain, jaise rolling counts aur fraud models ke features. Streaming complexity badhaati hai: late ya duplicate events, ordering aur exactly-once guarantees. Batch se shuru karo, aur streaming sirf wahan jodo jahan freshness sach mein zaroori hai.

🪜 Step by step

  1. Producers events (payment, click) hote hi Kafka topic pe bhejte hain.
  2. Kafka unhe order mein, partitions mein, tay time ke liye store karta hai, taaki kai consumers alag alag padh sakein.
  3. Consumers (Flink, Spark Streaming ya simple service) events process karte hain: filter, enrich, running counts.
  4. Results database, real time ML features ke liye feature store, ya alert mein jaate hain.
  5. Duplicates aur late events sambhalo: consumers idempotent banao aur event time windows use karo.

🔑 Key terms

Event
Kisi time pe hua ek fact, jaise '10:02 pe ₹499 ki payment'.
Topic
Kafka mein events ki naam wali stream.
Consumer
Service jo topic se events padhti aur process karti hai.

👀 Example dekho

text
UPI app ──payment event──▶ Kafka topic 'payments'
                                  │
          ┌───────────────────────┼───────────────────────┐
   fraud scorer            live dashboard          warehouse loader
   (reacts in < 1 s)       (updates per second)    (hourly batch)

Ek stream, kai independent consumers, har ek apni speed se.

⚠️ Aam galtiyaan jinse bachna hai

  • Jab hourly batch kaafi ho tab streaming chunna. Streaming banana aur chalana mushkil hai.
  • Maan lena ki har event bilkul ek baar aur order mein aayega. Duplicates aur deri ke liye plan karo.

✅ Quick check

Kis use case ko nightly batch ki jagah streaming sabse zyaada chahiye?

  1. Yearly HR summary
  2. Fraud payment ko hote hi block karna
  3. Monthly finance report
Jawaab dekho

B. Fraud payment ko hote hi block karna: Fraud ko seconds mein rokna hai. Kal ki report bahut der hai.

🙋 Seekhne wale yeh poochhte hain

Kya Kafka database hai?

Asal mein nahi. Yeh systems ke beech data le jaane ke liye durable event log hai. Results abhi bhi databases mein store karte ho.

Streaming AI mein kahan madad karti hai?

Fraud aur recommendations ke real time features, aur search ya vector indexes ko seconds mein up to date rakhne mein.

📌 Yaad rakho

Batch = periodic, simple. Streaming = real-time, complex. Jab seconds matter karein tab use karo.
