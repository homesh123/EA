🌳 Git and GitHub: saving and sharing your work

EnglishHinglish

🏠 Real-life example

Writing an important document, people save 'report_final', 'report_final_v2', 'report_FINAL_really'. Git does this properly. Each 'commit' is a labelled save point you can go back to. GitHub is like Google Drive for code: it keeps your project online and shows recruiters what you've built.

💡 In simple words

Git is a version-control tool. It tracks every change to your files so you can see history, undo mistakes and work with others without overwriting each other's work. The basic cycle is: edit files → 'git add' (choose changes) → 'git commit' (save with a message) → 'git push' (upload to GitHub). Branches let you try something new without breaking the main version. Your public GitHub profile is often the first thing an AI hiring manager looks at.

🎬 See how it works

Each dot is a commit (a save point). A branch lets you try something safely, then merge it back and push to GitHub.

🔑 Key terms

Commit
A saved snapshot of your project with a short message.
Repository (repo)
A project folder tracked by Git.
Branch
A separate line of work, so you can experiment safely.

👀 See it in action

bash
git init                         # start tracking this folder
git add analysis.py
git commit -m "Add sales analysis"
git push origin main             # upload to GitHub

Four commands you'll use every single day.

✅ Quick check

Which command creates a save point with a message?

  1. git init
  2. git commit
  3. git push
Show answer

B. git commit: commit saves a snapshot locally. push then uploads your commits to GitHub.

📌 Remember

add → commit → push. Commit small and often, with clear messages.
